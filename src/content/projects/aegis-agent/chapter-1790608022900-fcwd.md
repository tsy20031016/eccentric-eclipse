## 交互与接入域（Experience & Access）


一. FastAPI 接入层

当前已经有：
- FastAPI 应用工厂
- /api/v1 版本化接口
- Agent 执行接口
- 健康检查
- 工具清单
- Trace 查询
- RAG 查询
- Memory 查询
- OpenAPI /docs
- 依赖注入，可替换真实 AgentService
- 同步阻塞任务交给 FastAPI 线程池



二. 严格的请求响应契约

当前使用 Pydantic 严格 DTO，已经实现：

- 未知字段拒绝
- 字段长度限制
- session_id 格式检查
- Task 自动去除首尾空白
- 统一错误结构
- 422、413、404、500 错误语义
- 自动生成 OpenAPI 文档

三. 三层关联标识

现在已经有：

request_id
    ↓
input_id
    ↓
run_id
分别表示：
- request_id：一次 HTTP 请求
- input_id：标准化后的一次输入
- run_id：一次 Agent 执行
它们可以把：
API 请求
输入处理
Agent 执行
Trace 日志
关联起来。
这个设计很适合继续扩展成完整的 Interaction ID 和事件链。

四. Input Gateway 输入网关

已经完成的处理链：

外部输入
  ↓
类型识别
  ↓
内容解析
  ↓
标准化
  ↓
大小和合法性校验
  ↓
AgentInput
支持九种输入类型：
- 普通文本
- 代码
- JSON
- CSV
- Markdown
- XML
- 结构化文本
- 文件
- 二进制

已经做了的设计：

- 声明类型只是 Hint
- MIME、扩展名、内容嗅探可以共同判断
- 无法解析不等于非法输入
- 解析失败时保留原文
- HTTP DTO 与内部领域模型分离
- Input Gateway 不负责理解任务意图
- 超限统一由 Validator 裁决

五. 多内容输入模型

Agent 接口已经支持：
{
  "task": "分析这些数据",
  "contents": [
    {
      "text": "...",
      "content_type": "csv",
      "filename": "sales.csv"
    }
  ],
  "attachments": [
    {
      "filename": "report.pdf",
      "mime_type": "application/pdf",
      "size": 102400
    }
  ]
}
目前 contents 可以承载正文，attachments 只承载描述信息。
这里需要注意：
当前还不是真正的文件上传系统。附件没有承载文件内容，也没有文件存储和生命周期。

六. 结构化 Agent 响应

当前响应已经包含：

- 最终回答
- 模型决策步数
- 工具调用轨迹
- 使用过的工具
- RAG 引用
- 涉及的记忆
- 是否触发步数上限
- 模型提供方
- 模型 ID
- 服务端耗时
- request_id
- input_id
- run_id
- session_id

七. 会话入口

已经支持：
{
  "task": "继续刚才的问题",
  "session_id": "session-001"
}
启用 Memory 后，同一个 session_id 可以映射到 LangGraph thread_id，继续多轮上下文。
