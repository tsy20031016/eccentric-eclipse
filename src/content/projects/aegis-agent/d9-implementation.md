## 设计目的与位置

D9 回答三个问题：这项任务需要哪个时间点的数据；获取到的数据是否满足要求；满足要求的数据能在什么范围、多久内复用。它位于节点级 D8/D7 复检之后、D10 执行形态定稿之前，输出可写入 Query IR 的逐需求时效契约。

“快衰减 / 慢衰减”是展示标签。实际裁决依赖企业策略、来源证据和用户约束；未知保持 `indeterminate`，不把估计的答案半衰期直接换算成 TTL。

## 两个阶段

**规划阶段**由 `TemporalPlanningService` 接收 D3 的信息需求、可信主体、逐需求的节点复检结果和显式时间约束。每项需求匹配一个版本化企业规则，生成 `TemporalRequirement`；缺失、冲突、范围不一致或策略漂移会产生未决结果。此阶段只制定契约，不读取业务数据。

**运行阶段**由 `TemporalReadService` 执行纯读取。每次请求先重新裁决 D8/D7、履行权限义务，再查缓存或回源。核验来源身份、资源 ID、资源版本、数据等级与时间证据；数据交付前再次复检动作绑定。缓存内的旧授权不能代替当前授权。

## 时效模式与保存范围独立

三种时效模式分别是：`max_age` 限制业务数据年龄；`require_revalidation` 要求本次操作向来源核验；`version_pinned` 固定不可变版本。用户要求“当前”会加强为来源核验，显式版本必须匹配，历史 `as_of` 必须精确匹配。历史快照以指定时间作为年龄参照。

保存范围分别是 `no_store`、`request_local`、`principal_scoped`、`tenant_scoped`、`public_shared`。可保存不代表可直接复用，必须重新满足时效与授权。共享范围需要可信调用方提供“可见内容投影一致”的分区；当前所有键保留租户隔离，即使公开来源也不跨租户共享。

企业年龄上限、用户上限和来源上限取最严格值；保存期限也取企业与来源的最短期限。来源禁止保存优先。示例 JSON 中的阈值用于离线演示，企业需要按业务制定规则。

## 时间证据

`DataFreshnessEvidence` 将 `fetched_at`（下载时间）、`data_as_of`（业务截至时间）与 `validated_at`（来源核验时间）分开记录。重新下载旧报告不会刷新报告的业务年龄。缓存条目中的旧核验时间不能证明本次请求已核验；运行时必须重新调用可信来源验证器。

未来时间、缺失必需业务时间、版本冲突和过期证据会触发回源或未决。`aggregate_plan_freshness()` 检查所有必要需求的精确覆盖，整体复用要求每项均满足，不能用平均新鲜度掩盖某个过期来源。跨系统的一致快照还需要连接器提供业务一致性标识；逐项时效通过不自动证明事务一致性。

## 缓存隔离、失效与失败语义

缓存键绑定租户、主体或可信共享分区、权限快照、权限/红线/风险/时效策略版本、工具参数、资源版本和时间约束。参数参与哈希计算，审计摘要不输出参数正文或数据正文。

`InMemoryTemporalCache` 限制条目数与正文总字节数，支持到期清理和按租户、主体、来源、资源或策略版本失效。失效操作增加全局 generation；回源期间若发生失效，旧 generation 不能写回，也不能交付该次结果。全局 epoch 是保守实现，会同时阻断其他正在读取的缓存分区。

缓存后端故障可在授权有效时回源；来源、权限或策略证据未知时不能交付数据。旧值降级只在企业明确配置宽限窗口、来源读取失败、只读低严重度且用户没有当前性或历史精确约束时允许，并返回真实 `data_as_of` 和 `REUSE_STALE`。写操作、外部披露和人工审批结果不进入这条复用路径。

## 模块实现

- `models.py`：契约、模式、时间证据、数据快照和结果。
- `policy.py`：可替换策略协议、确定性 JSON 规则与严格加载。
- `service.py`：逐需求规划及策略收敛。
- `freshness.py`：纯函数时效校验及必要需求聚合。
- `runtime.py`：D8/D7 门控、来源核验、回源、交付前复检与受控复用。
- `store.py`：缓存协议、有界内存实现和 generation 失效。
- `factory.py`：通过 `Settings.temporal_policy_path` 独立装配。

## 交付边界

当前模块及实际受控读取路径可独立调用，32 条针对性离线用例覆盖关键裁决。它尚未接入主 Agent / HTTP 工具路径；设置 `TEMPORAL_POLICY_PATH` 不会自动开启答案缓存。当前缓存是进程内实现，重启后丢失；持久化加密、跨进程原子失效、企业 IAM/来源适配器、事件总线订阅、指标导出与最终答案缓存均需后续集成。

生产适配器必须保障：真实调用参数对应绑定资源；验证结果来自可信来源；共享投影由服务端生成；失效事件可靠传递；缓存保存与删除满足企业数据保留规则。D6 负责业务正确性验收，D9 的新鲜度结论不能替代 D6。
