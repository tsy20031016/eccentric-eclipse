## 1. 目的

D5 回答“当前已知的任务图能否在执行前完整编译；中间结果是否会要求增加新节点或依赖”。它不重复 D4 的拓扑分类：同一条链可以是完整链，也可以只是开放调查的已知前缀；有条件分支或有界重试的图仍可能是静态可编译图。

`H(G∣Intent)` 是概念性判据，不从单次模型输出计算数值。工程判定使用经 D4 校验的图、`complete` 声明及逐项 `StructureGap`，不制造没有校准依据的熵分数。

## 2. 三种结果

- `static`：候选图声明完整、无未知或扩展缺口。执行时从已声明分支中选择路径，或者按已知模板批量处理对象，都不改变流程结构。有上限的重试也属于此类。
- `dynamic_replan`：已知图中某个节点后明确存在 `expansion` 缺口，必须先取得中间结果，再增添新节点或依赖。结果保存触发节点 ID；这只是**重规划需求标记**，不表示当前已经有安全的重规划执行器。
- `indeterminate`：D4 未给出有效图、存在 `unknown` 缺口，或候选图未证明完整且没有明确扩展依据。未知优先于动态扩展，避免把缺少的事实误报为已知的重规划需求。

D4 上游不适用时，D5 返回 `not_applicable`。每种结果保留稳定原因码，供 Query IR、观测和后续策略使用。

## 3. 与 D4 的证据关系

D4 先保证节点/边证据有原文依据，普通流程无环，反馈有界，并验证 `choice` 缺口确实指向已声明的选择分支。`choice` 只意味着运行时路由，不触发 `dynamic_replan`。`expansion` 表示流程模板本身要增加节点或边；图完整时不得同时声明扩展或未知缺口。

动态批量需区分**实例数量**与**模板结构**：例如“对所有合同执行同一检查，再汇总”是固定批量模板；“检查第一份合同后，根据发现决定新增哪些检查”才是重规划。D5 不决定是否准许执行新增节点；每次扩展都必须重新经过图校验、D6 和计划后 D8/D7 复检。

## 4. 当前限制

`complete=true` 仍来自候选证据提取，结构校验不能数学证明“没有遗漏任务”。因此 `static` 表示**依据当前已验证证据可编译**，不是对真实业务流程完整性的形式证明。未来需通过标注样本评估遗漏率；复杂流程可引入规则模板或正式工作流定义作为更可信的完整性依据。

`app/task_structure/d5.py` 实现确定性服务。S20 的 D4/D5 联合验收为 20 条离线用例，S25 已将 D5 接入主编译链。当前可以识别重规划需求，但通用运行时重规划器仍未完成；新增节点和依赖不能绕过新的计划修订与复检。
