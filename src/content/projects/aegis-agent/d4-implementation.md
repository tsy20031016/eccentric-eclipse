## 1. 目的与边界

D4 回答“当前已知的任务如何依赖、哪些控制路径可以被声明”。结果用于后续 D6 节点验证、计划后 D8/D7 复检和执行调度；D4 本身**不执行任务、不授予权限，也不把结构上可并行等同于准许并行执行**。LangGraph 的 Agent 运行图与这里的用户任务图是两种不同对象。

上游须先完成 D1 → D8 计划前剪枝 → D7 预分类 → D2/D3。`StructureContext` 使用 D8 已允许的 `ScopedProblem` 和 D2/D3 结果。服务再次检查能力键、D7 后果清单和 D2/D3 状态。D8 未放行返回 `not_applicable`；范围冲突、D2/D3 未决和图证据无效返回 `indeterminate`。S25 已将该契约接入统一编译链，但结构校验不能单独证明任务文本已完成语义剪枝。

## 2. 一张图，两类输出

`GraphEvidence` 保存节点、边、结构缺口、完整性声明和来源。节点提供动作、等待、批量、结束类型；出边分叉为 `exclusive` / `inclusive` / `parallel`；入边汇合为 `all` / `any` / `quorum`。`all` 指所有**已激活**的前驱，`quorum` 指明确数量的前驱。等待区分人工、外部事件和定时器；批量节点保存原文中的集合来源。多个节点引用同一 `resource_key` 时只标记共享资源，不在 D4 内确定锁或并发数。

边区分普通依赖、条件守卫、有界重试、失败、补偿和取消。条件只保存原文证据，**绝不作为代码执行**。补偿边指出被撤销动作与补偿动作，并绑定触发失败的节点；它必须对应一条失败边。取消边必须通向结束节点。常规依赖及条件边必须构成 DAG；重试边单独表示反馈，须有 1–10 次上限，且确实回到当前流程的前驱。普通依赖环、悬空节点和无界反馈一律无效。

在经过图校验后，D4 确定性计算基础拓扑：`single`、`independent`、`chain`、`tree`、`general_dag`。守卫、分叉模式、汇合模式、等待、批量、重试、异常/补偿/取消和共享资源作为可组合的 `features` 输出。这样不会把“Petri 网”“守卫”与图形状混成互斥类别。

## 3. 证据与可信边界

可替换的 `GraphEvidenceExtractor` 负责提出候选图；默认适配器调用项目已配置的 OpenAI Compatible 模型。严格 JSON 解析限制字段、枚举和数据类型；服务再检查节点/边/缺口的证据片段逐字出现于已剪枝任务文本、能力键属于允许片段、拓扑和控制语义有效。旧版 `TaskGraph.from_steps()` 的 `linear_fallback` 不能证明用户任务为链式，D4 显式拒绝非提取器来源。

**原文锚定不等于语义正确。** 模型仍可能遗漏步骤、错误建立依赖，或错误声称图已完整。当前离线测试验证结构规则和失败收敛；语义召回率需要后续标注集评测。节点能力键可以留空；有工具调用或具体资源时，计划后 D8/D7 仍必须按真实节点及参数复检。

## 4. 企业范围与后续扩展

当前表达了企业常见的多部门同步、审批等待、事件等待、批量模板、有限重试、失败补偿与取消路径。`batch` 表示固定流程模板作用于一组对象；集合成员运行时才出现不自动意味着 D5 动态重规划。`resource_key` 只揭示潜在冲突，真正的锁、配额、超时、幂等、持久化恢复和补偿执行属于后续执行层。

本阶段没有引入 Petri 网执行器。若以后需要证明复杂同步或死锁性质，可从已验证的图契约向专门的工作流验证器转换。代码入口：模型、图证据提取、D4 分类与校验、运行时装配。


## 5. 验收与主链接入

S20 的 D4/D5 联合验收为 20 条离线用例。S25 已接入静态依赖图执行；条件守卫、反馈、等待、动态批次等复杂控制流要求可信适配器，不会被降级为无条件 DAG 执行。
