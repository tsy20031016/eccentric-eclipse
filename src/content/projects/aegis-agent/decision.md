## 理解、决策与规划域负责将用户请求转化为具有明确目标、信息依据、行动步骤和验证要求的结构化计划，并判断当前请求是否具备继续执行的条件。


## 本域以用户问题十维解构体系为核心，通过 QueryCompiler 串联各维度，输出统一的 QueryIR 或明确的未决状态，供 Agent Runtime 调度。


## 1.职责与设计目标：

## 核心问题：

- 用户希望完成什么，意图是否明确；
- 问题属于什么类型，任务定义是否充分；
- 完成任务需要哪些信息，信息是否具备可信来源；
- 任务如何拆分，各步骤之间有什么依赖；
- 任务结构能否预先确定，是否需要动态调整；
- 如何验证各步骤的结果；
- 在权限、风险及时效约束下，是否可以继续；
- 任务应由哪些角色承担，需要哪些能力和预算。

## 十维解构在本域中的职责如下：

- D1 意图解析：分析意图确定性，识别需要澄清的请求。
- D2 问题类型：判断计算目标及任务定义是否充分。
- D3 信息需求与来源：识别信息缺口，核实来源与信息闭合情况。
- D4 任务结构：形成任务节点、依赖关系和控制语义。
- D5 结构确定性：判断计划是否能够预先确定，识别动态重规划需求。
- D6 验证方案：为节点结果制定必要断言和验证要求。
- D7 风险与后果：调用治理服务，获得风险结论及人工确认义务。
- D8 权限与边界：调用治理服务，确认允许的能力与具体动作。
- D9 时效契约：明确输入、来源和结果的时效要求。
- D10 执行形态：规划角色分工、能力需求、委派范围与预算。


设计上遵循“模型提取与提议、可信服务校验、确定性规则裁决”的原则。模型负责理解自然语言和提出候选动作；权限、风险、资源绑定及执行资格由可信策略和服务判断。
本域负责形成计划和决策依据，实际工具调用、运行状态推进及执行期复检由 Agent Runtime 负责。权限与风险规则归共享基础与治理域所有，信息读取和工具能力由能力与数据服务域提供。

## 2.接口与数据流


主要输入包括：

- 接入域标准化后的 AgentInput，包含原始文本、解析结果及上下文；
- 认证边界提供的可信 PrincipalContext；
- 服务端装配的权限策略、风险策略、来源目录、验证器注册表和角色目录；
- 可用工具的可信适配器及能力描述。
用户文本和模型输出不能直接构造可信身份、授予权限或声明某个资源已获授权。

输出:

编译结果为统一的 QueryIR 或明确状态。

QueryIR 汇集意图、问题类型、信息需求、任务图、实际动作、验证方案、权限与风险结论、时效契约以及执行形态等计划期事实，并携带相关版本和指纹。

只有状态为 READY 的请求可以进入执行。需要认证、澄清、审批，或存在拒绝及其他未决条件时，返回对应状态及原因，由 Runtime 停止当前执行分支。

当前编译顺序为：
标准化输入与可信主体

    ↓

D1 意图解析

    ↓

D8 计划前权限

    ↓

D7 计划前风险

    ↓

D2 问题类型

    ↓

D3 信息需求与来源

    ↓

D4 任务图 → D5 结构确定性

    ↓

D6 节点验证方案

    ↓

动作提议与可信资源绑定

    ↓

D8 计划后权限 → D7 计划后风险

    ↓

D9 时效契约

    ↓

D10 角色、委派与预算

    ↓

QueryIR 或未决状态



计划前检查用于确定允许的能力范围。实际工具、参数和目标资源确定后，再进行计划后复检，避免将粗粒度能力许可误当作具体动作授权。
执行过程中，Runtime 继续检查当前权限、风险、来源时效和验证结果。计划期通过检查，只说明当时满足条件。


## 4.实现步骤

1. 建立独立的维度服务

将意图分析、问题类型、信息闭合、任务结构、验证规划、时效规划和执行形态分别实现为独立模块。

每个模块通过结构化契约传递事实和结论，保持分析、裁决与执行之间的边界，便于单独测试和替换实现。

2. 分离模型提取与规则裁决

模型输出必须经过结构校验和领域约束检查。

例如，模型可以提出信息需求、任务节点和工具参数；服务端需要进一步核实来源、检查能力范围，并确认动作是否属于获准任务图。证据不足时保留未决状态，避免补造事实。

3. 构建任务图与验证计划

D4 描述节点及依赖，独立保留条件、等待、反馈和补偿等控制语义；D5 判断这些结构能否在执行前确定。

D6 将成功标准落实为节点级必要断言，并从可信注册表中选择验证能力。验证结论限定在具体断言范围内，例如数值相等只能证明该数值断言成立。

4. 绑定实际动作与资源

ActionPlanner 提出工具调用，可信适配器将工具、能力、参数和目标资源绑定为结构化动作。

当前 LLMActionPlanner 只允许为已有 action 节点提出调用，不能自行增加节点或能力。依赖尚未产生的结果、无法确定实际参数时，交回未决或重新规划流程。

5. 统一编译并交给 Runtime

QueryCompiler 按固定顺序串联各维度，检查阶段结果并汇总为 QueryIR。

QueryOrchestrator 根据编译状态选择执行或返回未决结果。未决请求不会降级到直接执行路径。

当前通过 QUERY_COMPILER_ENABLED 控制该链路，默认关闭；开启后优先使用统一编译与受控执行分支。

## 5.测试与验证

测试默认离线，使用模型替身和可信适配器验证领域规则与链路行为。

主要验证场景包括：

- 意图不明确时提前停止，返回澄清需求；
- 身份缺失或伪造时阻断执行；
- 权限拒绝及能力剪枝后，动作不能超出获准范围；
- 模型生成非法参数、未知节点或越权动作时拒绝编译；
- 信息来源缺失、版本漂移或过期时阻断相关流程；
- 必要验证失败时阻止结果交付；
- 需要人工审批时返回绑定动作的待审信息；
- 仅 READY 状态进入执行，执行期间权限撤销仍可阻断动作。


S25 统一接线阶段记录的全量验收结果为 1321 passed、2 deselected、1 warning，ruff 检查和格式检查通过。其中新增 21 条离线用例覆盖编译关口顺序、计算器执行、身份伪造、参数攻击、权限撤销、验证失败和来源过期等场景。该结果属于当时的阶段验收记录，未包含真实企业账号及线上模型分类准确率验证。

当前局限包括：

- 内置受控生产装配主要支持计算器，RAG、记忆和企业工具仍需可信适配；
- 静态依赖图与字面参数可执行，复杂控制流和依赖结果的参数绑定仍需完善；
- 已有待审批对象与动作指纹，但审批签发、持久化及批准后恢复尚未交付；
- 编译路径尚未复用旧 ReAct 会话历史，长期记忆工具尚未启用；
- 已有角色规划与运行内核，分布式工作进程和并行执行仍需生产适配。

## 6.后续计划

后续工作沿现有十维体系推进：

1. 完善澄清续接：将用户补充信息关联到原请求，重新编译并校验已有结论。
2. 支持结果参数绑定：为下游动作安全引用上游产物建立明确契约。
3. 完善动态重规划：根据执行结果或环境变化修订计划，并重新检查权限、风险和验证要求。
4. 扩展复杂任务控制流：逐步实现条件、等待、有限反馈、动态批次及补偿机制。
5. 接入更多可信能力：完成 RAG、记忆和企业来源的资源与来源适配。
6. 补齐跨域闭环：协同治理域与 Runtime 实现审批恢复、计划版本校验和执行前复检。
7. 开展真实场景评测：验证意图理解、信息缺口识别和规划质量，分别记录规划正确性、执行成功率及阻断原因。
