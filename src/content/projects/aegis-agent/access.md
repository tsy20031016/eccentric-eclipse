已检查接入层、DTO、输入网关、身份模型、Agent 会话接线和前端调用代码。我的判断是：现有功能适合演示与本地使用，企业化改造应优先补齐可信身份、数据隔离和资源保护，再扩展交互能力。

##  一、代码核查发现

1. 可信身份有接口，尚未形成完整认证入口。
   [main.py (line 213)](D:/AI_Project/aegis-agent/app/main.py:213) 从 request.state.principal 读取 PrincipalContext，这个边界正确，但应用工厂没有装配认证中间件。身份目前只在 Query Compiler 路径下传给执行服务。

2. 查询接口缺少身份和资源访问检查。
   Trace 列表与详情、Memory 查询、RAG 查询没有接入身份依赖。Memory 的客户端 scope 只是筛选条件，不能承担权限控制。

3. 会话标识还没有绑定主体。
   当前 session_id 直接映射到 LangGraph thread_id。企业环境需要绑定租户和用户，防止不同主体用相同会话标识访问同一段历史。

4. 输入超限检查晚于解析。
   [pipeline.py](D:/AI_Project/aegis-agent/app/input/pipeline.py) 先解析、标准化，再调用 Validator。超大 JSON、CSV 等会在拒绝前消耗资源；目前也没有请求体总字节限制。total_size 混合了文本字符数与附件声明字节数，需要统一语义。

5. 契约与错误处理仍需收紧。
   extra="forbid" 已实现，但不等同于严格类型模式，例如整数字段仍可能接受类型转换。500 响应直接返回异常类型和文本；全局 ValueError → 422 也可能把内部错误误判为客户端错误。

6. 关联标识、日志和控制台尚未统一。
   X-Request-ID 直接采用客户端值，成功与异常处理分别生成标识，缺少全局入口管理。日志记录任务前 80 个字符；/health 返回配置细节。前端执行页只提交任务和会话，尚未提供多内容输入，也没有统一超时、认证失效处理。

## 二、建议的企业化目标

Section 1 对外提供稳定契约，对内输出两个独立对象：
- AgentInput：用户给了什么、来源、解析状态、标准化内容。
- PrincipalContext：经过认证的主体、租户及可信身份属性。
任务意图和业务权限仍交给后续模块。Section 1 负责认证接入，并在资源查询入口调用权限模块作出访问裁决。

## 三、调整方案与实施顺序

Section 1.1：可信身份与资源访问边界——建议首先实施
- 新增 app/access/，集中实现认证适配器、身份依赖和请求上下文。
- 优先对接企业现有 OIDC/SSO；提供离线认证替身用于测试。
- 生产环境拒绝匿名业务访问；本地演示身份仅允许在明确的开发配置中启用。
- 忽略客户端自行声明的租户、角色和权限，身份由认证结果构造。
- 会话通过服务端绑定租户、主体与外部 session_id，统一覆盖两条执行路径。
- Trace、Memory、RAG 调用资源权限接口；列表先过滤授权数据再分页，详情检查归属。
- 存量记录缺少归属时，默认不对普通企业用户开放。
**验收重点：**伪造身份无效、跨用户同名会话隔离、跨租户查询被拒绝、身份能贯穿实际执行路径。RAG 的租户隔离还需知识库模块配合，不能只在 HTTP 层增加认证就宣称完成。

Section 1.2：输入资源保护与契约治理
- 增加读取请求体时的字节上限，不能只依赖 Content-Length。
- 将 Validator 分为解析前的原始输入校验和解析后的结果校验。
- 从 Settings 注入条数、单项大小、总字节数及解析结构预算。
- 分开记录实际文本字节数与附件声明大小。
- 保留“解析失败保留原文”的行为，同时限制解析资源消耗。
- 对数量、大小等关键字段启用严格类型；明确兼容性变化。
- 保留现有错误外层结构，补充稳定错误码和字段级详情，统一 OpenAPI 声明。
- 按请求覆盖 system_prompt 改为受控调试能力，生产普通用户关闭。
**验收重点：**超限输入在解析前拒绝；中文大小计算正确；非法类型与内部异常准确区分。

Section 1.3：请求治理与运维可观测性
- 中间件统一生成或校验 request_id，成功和失败都返回同一响应头。
- 保留三层标识，不急于新增 interaction_id；先补齐它们在执行记录中的关联。
- 500 对外返回通用信息，详细异常留在服务端。
- 日志默认记录标识、状态、大小和耗时，正文采集显式配置。
- 拆分存活检查、就绪检查和受保护的诊断信息。
- 增加并发准入、排队上限及明确的超载响应；多实例限制需要共享设施。
- 明确客户端超时不代表服务端执行取消，避免产生重复执行。

Section 1.4：企业控制台交互
- 增加身份状态、认证失效提示和无权限状态。
- 支持多内容编辑、类型提示及解析告警。
- 明确附件当前仅为描述信息。
- 统一处理 401、403、413、429、503、网络失败和超时。
- 展示服务端返回的会话标识，支持复制关联 ID、跳转 Trace。
- 生产构建关闭自动演示数据回退；演示版本继续明确标识快照来源。
- 前端类型逐步从 OpenAPI 生成，减少前后端契约漂移。
真正的文件上传与生命周期、异步任务、取消和流式输出，建议另设后续阶段。
